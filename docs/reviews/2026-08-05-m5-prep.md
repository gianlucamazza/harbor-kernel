**Date:** 2026-08-05 (desk); S0–S4 closed on QEMU the same day.  
**Scope:** R1, R2, R3, R10 (boundary for M5 only — not full R1–R12).  
**Method:** desk analysis against [ADR-0012](../adr/0012-frame-allocator-for-address-spaces.md)

[ADR-0006](../adr/0006-cooperative-execution-model.md), then `sched` / `mmu` /

**Gate:** [ADR-0001](../adr/0001-multi-role-analysis.md) — findings that move a

---

## Executive summary

M5 done-when is clear: one EL0 task in its own `TTBR0`, permission fault on a
kernel address with ESR recorded, `SVC` round-trip. ADR-0012 correctly splits
**kernel table arena** vs **user frame pool**. The main risks are not “missing
a buddy allocator” but **entry/exit discipline**, **which TTBR holds the
kernel**, and **not freeing user frames**.

No P0 design hole found that would force reopening 0005/0006. Recommended
implementation order is **frame math (done in `kernel-core`) → named phys pool
+ kernel wrapper → AS object + map helpers → EL0 entry stub → fault/SVC
probes**.

## Per role

### R1 — Layering

- Today: `exception` → only `irq`; `sched` → `arch`+`mm`; `ipc` → `sched`.
- M5 will need something like `aspace` or `mm::user` used from bootstrap and
  from the SVC/sync exception path. **Rule:** exception still must not import
  BSP or drivers; current AS handle via `arch` or a sealed policy module.
- Frame pure math stays in `kernel-core` (no MMIO) — clean.

### R2 — Memory / MMU

- **Keep** ADR-0005 arena for kernel tables only (boot identity, splits).
- **New** phys pool for user Lx tables + user pages (ADR-0012).
- AArch64 long-term: **TTBR1 = kernel high**, **TTBR0 = user**. **M5 v1**
  (ADR-0014): stay **TTBR0-only** (`EPD1`); each user AS carries kernel identity
  maps (EL0-denied) plus a private user window. TTBR1 migration is a successor ADR.
- Teardown: free every frame the AS allocated (spawn/exit loop must not leak).

### R3 — IRQ / exceptions

- EL0 sync faults and SVC enter EL1 with DAIF policy consistent with today
  (mask for bookkeeping).
- Must **not** call `yield_now` / `context_switch` from the vector path except
  through the same voluntary rules as today (return to thread, then schedule).
- IRQ wake queue (ADR-0008) stays for device IRQs; not for SVC.

### R10 — Roadmap / agents

- M5 delivers **address-space separation + EL0**, not full multi-agent product.
- Caps stay EL1 tables until M5 decides EL0-visible cap ops (can remain kernel
  only for v1 SVC: `send`/`recv` wrappers later).
- M6 still blocked on 0013 accept + M5 HW.
